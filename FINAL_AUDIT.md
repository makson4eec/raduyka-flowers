# Финальная проверка проекта

Дата проверки: 2026-08-10.

## Что проверено

- 11 автоматических тестов бонусов и дат напоминаний — все проходят.
- 66 файлов TypeScript/TSX — синтаксических ошибок не найдено.
- Внутренние импорты `@/` и относительные импорты — отсутствующих файлов не найдено.
- JSON-файлы проекта корректно разбираются.
- Все статические пути `/images/...`, используемые приложением, существуют.
- Рабочий код не читает и не записывает `data/store.json`; он используется только одноразовым migration-скриптом.
- Загружаемые фотографии сохраняются в Supabase Storage (`product-images`).
- Валидатор товара принимает public URL только из настроенного Supabase-проекта и отвергает посторонний origin.
- CSP разрешает изображения из настроенного Supabase origin.
- `.env.local`, Firebase Admin SDK JSON, приватные ключи, `.next`, `node_modules` и локальный store исключены из Git.

## Дополнительные исправления перед архивом

- Убран устаревший `Admin_password`: используется только `ADMIN_PASSWORD`.
- Удалён development-only metadata `codex-preview`.
- Для production-ссылок регистрации/сброса пароля добавлен безопасный fallback на Vercel production URL, если `SITE_URL` ещё не задан.
- Минимальная длина `CRON_SECRET` в проверке приведена к 16 символам.
- API товаров теперь возвращает корректные 400/404/409 вместо 500 для ожидаемых ошибок магазина.
- Добавлены нейтральные локальные placeholder-изображения для отсутствующих фото, чтобы до загрузки реальных фотографий не было битых картинок.
- README заменён на актуальную инструкцию для Радуйки/Supabase/Vercel.

## Что нужно проверить на компьютере перед Deploy

Полный `next build` в текущей служебной среде не был завершён, потому что npm registry здесь зависает при скачивании зависимостей. Это ограничение среды проверки, а не результат ошибки сборки.

На рабочем компьютере выполнить:

```powershell
npm.cmd test
npm.cmd run build
```

После успешного build можно отправлять изменения в GitHub и делать Vercel Deploy.
