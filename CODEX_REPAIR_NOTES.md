# Исправления после прерванного аудита Codex

Сохранены все новые функции магазина: размеры букетов, добавки, открытка, конструктор, корзина, бонусы, Supabase, Firebase Push и cron.

Исправлено:

- `npm test` теперь работает на Node 22 через встроенный type stripping.
- Пароль покупателя снова минимум 8 символов, как настроено в Supabase.
- Усиленный пароль администратора (16+) обязателен в production, но старый локальный пароль больше не блокирует разработку.
- Вход администратора и загрузка фото не требуют обязательного `Content-Length`, который может отсутствовать за HTTP/2/прокси. Ограничения размера всё равно сохраняются.
- Cron может повторить полностью неудачную отправку push и восстановить зависший `processing` после 15 минут; успешные/частичные отправки по-прежнему не дублируются.
- SQL получил одноразовый repair-migration для уже подтверждённого пользователя, созданного до появления бонусной системы.

## После копирования файлов

1. Не удаляйте свой `.env.local`.
2. Выполните `npm.cmd install`.
3. Выполните `npm.cmd test`.
4. Выполните `npm.cmd run build`.
5. В Supabase SQL Editor один раз снова выполните актуальный `supabase/schema.sql`, чтобы добавить бонусные таблицы/RPC и repair-migration.
6. Затем проверьте `/admin`, `/register`, `/account`, добавление товара в корзину и один тестовый push.

`supabase/schema.sql` рассчитан на повторный запуск: таблицы создаются через `if not exists`, а политики/триггеры пересоздаются предсказуемо. Перед production всё равно держите резервную копию базы.
