# Радуйка — интернет-магазин цветов

Next.js-приложение магазина «Радуйка»: каталог, конструктор букета, корзина и заказы, админ-панель, личный кабинет, бонусы, важные даты и Web Push-напоминания.

## Что используется

- Next.js 16 / React 19 / TypeScript
- Supabase Auth + Postgres
- Supabase Storage (`product-images`) для фотографий товаров
- Firebase Cloud Messaging для Web Push
- Vercel Cron для ежедневной отправки напоминаний

## Локальный запуск

Требуется Node.js 22+.

```powershell
npm.cmd install
npm.cmd test
npm.cmd run dev
```

Сайт: `http://localhost:3000`  
Админка: `http://localhost:3000/admin`

Перед production-развёртыванием также проверьте:

```powershell
npm.cmd run build
```

## Supabase

Для нового проекта последовательно выполните в SQL Editor:

1. `supabase/schema.sql` — профили, напоминания, push-подписки и журнал уведомлений.
2. `supabase/store.sql` — товары и заказы.
3. `supabase/migrations/2026-08-17-legal-readiness.sql` — юридические поля заказа и товаров.
4. `supabase/migrations/2026-08-20-yookassa-sbp.sql` — служебные поля платежей ЮKassa/СБП.
5. `supabase/migrations/2026-11-25-categories-and-product-images.sql` — категории, три фото товара и редактирование информации сайта.

В Supabase Storage создайте публичный bucket:

```text
product-images
```

Рекомендуемые ограничения bucket: изображения JPG/PNG/WebP, до 5 МБ.

Если остался старый локальный `data/store.json`, его можно один раз перенести:

```powershell
npm.cmd run migrate:supabase
```

Рабочее приложение после миграции не зависит от `data/store.json` и не сохраняет загруженные картинки в файловую систему Vercel.

## Управление магазином

Для обновления существующего проекта один раз выполните в Supabase SQL Editor файл `supabase/migrations/2026-11-25-categories-and-product-images.sql`, затем разверните новую версию приложения. Миграция сохраняет товары и заказы, создаёт текущие категории и закрывает прямое редактирование новых таблиц для посетителей сайта.

В `/admin` доступны:

- **Товары** — создание, редактирование, скрытие и удаление товаров, выбор категории и до трёх фотографий. Первое фото используется на витрине; остальные доступны в галерее товара. У цветов сохраняется выбор цвета с отдельными фотографиями и ценами.
- **Категории** — создание, редактирование названия, фотографии, описания, порядка, фона и видимости. В категории с товарами сначала перенесите или удалите товары, затем удаляйте саму категорию. Скрытие категории скрывает её карточку и фильтр, но не сами товары.
- **Информация** — контакты, часы работы, адреса, карта, реквизиты и 11 информационных страниц: доставка, оплата, возвраты, «О нас», поводы и юридические документы. Для страниц доступны заголовок, текст, предпросмотр и восстановление исходной страницы. Текст поддерживает абзацы, заголовки `##`, списки, выделение и ссылки. HTML не исполняется. После сохранения страницы публикуются с указанным заголовком и текстом; восстановление возвращает исходное оформление.

Места `{{phone}}`, `{{email}}`, `{{address}}` и другие поля реквизитов в тексте подставляются из настроек магазина. `{{documentVersion}}` обозначает текущую версию документа. При изменении документов или реквизитов сервер обновляет версии, которые фиксируются при оформлении заказа и регистрации. До первого редактирования используются существующие тексты и оформление. Изменения сохраняются в Supabase; локальные файлы или повторная сборка для редактирования содержимого не нужны.

## Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните значения. Секреты нельзя коммитить в Git.

Критичные server-only переменные:

- `ADMIN_PASSWORD`
- `SUPABASE_SERVICE_ROLE_KEY`
- `FIREBASE_PROJECT_ID`
- `FIREBASE_CLIENT_EMAIL`
- `FIREBASE_PRIVATE_KEY`
- `CRON_SECRET`
- `YOOKASSA_SHOP_ID`
- `YOOKASSA_SECRET_KEY`
- `YOOKASSA_RECEIPT_VAT_CODE`

Публичные Firebase/Supabase переменные уже имеют префикс `NEXT_PUBLIC_`.

После подключения постоянного домена задайте `SITE_URL=https://ваш-домен` и добавьте этот адрес в Supabase Auth URL Configuration. Для первой Vercel-публикации приложение умеет использовать системный production URL Vercel как безопасный запасной вариант.

## ЮKassa / СБП

Оплата создаётся только на сервере после того, как сотрудник сохранил окончательную стоимость доставки. Сумма берётся из сохранённого заказа, а не из браузера. Для платежа используется СБП (`payment_method_data.type = "sbp"`), автоматическое подтверждение (`capture = true`) и redirect-confirmation.

Перед проверкой оплаты:

1. Примените `supabase/migrations/2026-08-20-yookassa-sbp.sql`.
2. Заполните `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` и `YOOKASSA_RECEIPT_VAT_CODE`. `YOOKASSA_RECEIPT_TAX_SYSTEM_CODE` указывайте только в соответствии с вашей системой налогообложения и настройкой чеков.
3. В личном кабинете ЮKassa откройте **Интеграция → HTTP-уведомления**, укажите `https://ваш-домен/api/yookassa/webhook` и включите события `payment.succeeded` и `payment.canceled`. URL должен быть публичным HTTPS-адресом.
4. В Vercel добавьте те же server-only переменные окружения и выполните новый Deploy.
5. Проверьте реальный сценарий: заказ → стоимость доставки → «Выставить оплату СБП» → открыть/скопировать ссылку → оплата → статус «Оплачено».

Webhook не доверяет входящему событию вслепую: приложение повторно запрашивает платёж у ЮKassa и сверяет ID, заказ, сумму, валюту, способ оплаты и статус.

Важно: тестовый магазин ЮKassa не поддерживает тестирование СБП так же, как банковские карты. Для проверки СБП нужен магазин, в котором этот способ оплаты действительно подключён.

## Vercel

1. Подключите GitHub-репозиторий.
2. Импортируйте переменные окружения из `.env.local` в Vercel Environment Variables.
3. Проверьте, что `ADMIN_PASSWORD` и `CRON_SECRET` заполнены надёжными значениями.
4. Выполните Deploy.
5. После появления production-адреса проверьте регистрацию, `/admin`, создание заказа, загрузку изображения и push-уведомления.

Cron уже описан в `vercel.json` и вызывает `/api/cron/reminders` ежедневно.

## Безопасность

`.gitignore` исключает `.env*`, Firebase Admin SDK JSON, приватные ключи, локальное хранилище заказов, `node_modules`, `.next` и `.vercel`.

## Юридическая готовность перед публичным запуском

Проект содержит юридические страницы, отдельное согласие на ПД, фиксацию версии оферты и дополнительные поля информации о товаре. Перед запуском обязательно выполните пункты из [`LEGAL_RELEASE_CHECKLIST.md`](./LEGAL_RELEASE_CHECKLIST.md), заполните `lib/legal.ts` и примените миграцию `supabase/migrations/2026-08-17-legal-readiness.sql`.

Подробный список внесённых изменений: [`LEGAL_CHANGELOG.md`](./LEGAL_CHANGELOG.md).
